Contratos existentes que devem ser estendidos sem criar outro transporte:

```typescript
interface SignalingState {
  isConnected: boolean;
  error: string | null;
  mutedUserIds: Set<string>;
  activeShare: ScreenSharePublicShare | null;
}

interface OwnedScreenShareLifecycle {
  generation: number;
  identity: string;
  companyId: string;
  spaceId: string;
  userId: string;
  presenceSessionId: string;
  manager: WebRTCManager;
  share: ScreenSharePublicShare | null;
  attached: boolean;
}

type ScreenShareStopReason =
  | 'user-stop'
  | 'track-ended'
  | 'scope-changed'
  | 'error-cleanup';
```

A rota `active` retorna `screenShareActiveResponseSchema` para sucesso, com `active` singleton ou `null`. Erros públicos usam `screenSharePublicErrorSchema`; `PRESENTER_PROFILE_INVALID` descreve o apresentador remoto, enquanto `SESSION_INVALID`, `MEMBERSHIP_SCOPE_INVALID`, `UNAUTHORIZED` e `ACCESS_DENIED` descrevem a autoridade do viewer.

`stopScreenShare()` já possui a ordem de propriedade necessária: aposenta a generation, aborta request, limpa heartbeat e listener, limpa estado de display, chama `manager.stopScreenShare(reason)` quando anexado, tenta release exata e preserva o manager de áudio.
